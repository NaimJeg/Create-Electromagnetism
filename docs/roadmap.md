# 实施、迁移与验证路线

修订日期：2026-11-03。路线以复用 CEE 为前提，没有新求解器或工期承诺。

## 1. 前三项交付

1. **依赖与能力基线**：固定制品版本、SHA-256 和对应源码提交；列出可复用、需要补齐、不在范围内的能力。构建文件锁定值不等于 README 声称的兼容范围。
2. **脱离游戏的模型测试集**：先抽出一个灯丝／热学模型和一个半导体模型，明确端口、参数、初值和时间步契约。模型测试不自行替代 CEE 电网；电网行为另用目标版本适配测试验证。
3. **可解释的性能基准**：记录阶段耗时、分解次数、迭代数、分配与 GC、主线程等待，判断是否真正需要改求解器。

当前缓存制品 `9173792` 声明 `1.21.1-1.1.4`，未含源码引用的 Norton 类。对应源码提交尚未确认。恢复构建与声明兼容范围是 M0 的工作，本次文档修订没有完成该项。[依赖证据](sources.md#local-baseline)

## 2. 阶段与退出条件

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| M0：锁定基线 | 制品与源码映射、接口矩阵、旧存档与行为清单 | 可构建且专用服务器可启动；记录已知缺陷 |
| M1：设备契约 | 纯模型、状态分层、CEE 适配映射、失败状态方案 | 不启动游戏可测模型；微步与迭代不会重复提交；未知状态不冒充收敛 |
| M2：纵向迁移 | 先灯具／加热，再半导体、励磁与其他内容 | CEE 电源→导线→本项目设备闭环；保存重载、拆除、卸载、旋转及机械反馈通过 |
| M3：诊断与性能 | 完整回归和分阶段基准 | 给出是否需要 CEE 局部改造的证据；改造前后精度一致可比 |
| M4：高频边界原型 | 受功率约束的收发模型、确定性输入、观测 | 欠压、限流、带载、供电中断和能量账本通过；声明信号抽象与采样限制 |
| M5：无线与仪器扩展 | 信道、调制与解调、示波器；按能力加入音频 | 相位／带宽／干扰可验证，DSP 与电网时间边界稳定；以实测决定规模 |

HB、自适应积分、独立内核只有在[ADR 启动条件](decisions/0001-independent-simulation.md)满足后另立里程碑。无线行为模型通过验收不代表已经支持任意晶体管 RF 电路。

## 3. 内容与存档迁移

| 内容 | 迁移重点 |
|---|---|
| 灯座、灯泡、生长灯、工厂灯 | 抽出热模型；微步有功累积，世界侧更新光照与作物 |
| 加热线圈 | 热量、温度与加工档位分离，避免重复记账 |
| 换向开关、导电外壳 | 保留端子和连接语义，明确拓扑变化范围 |
| 励磁定子、发电机集成 | 复用 CEE 机电设施，核验功率／应力反馈，逐项减少侵入补丁 |
| BJT／MOS | 工作区、反接、限流语义、非线性耦合与状态契约 |
| 电铃与世界效果 | 有效结果驱动；声音、粒子及损坏在世界边界执行 |
| 频率表、同步钟显示 | 保留 CEE 方块适配，统一相位、频率及测量窗口 |
| 雷击、电弧、触电 | 区分激励、电气支路与世界效果；检查跨存档缓存 |
| 已禁用电风扇、历史逆变器资源 | 不自动恢复或当作已实现功能承诺 |

先保留注册 ID、端子序号、导线与 CEE SavedData 引用。参数、已接受状态和缓存分开，不在模组内部另建版本契约、状态版本字段或迁移框架；模组版本匹配交给加载器，存档读写留在世界适配侧。不能把 RMS 当瞬时相位或凭空创建储能。

迁移在存档副本验证，覆盖灯泡安装、颜色、损坏、开关、器件参数、设备拆除和区块卸载；未知节点和失联引用提供诊断。当前不迁走 CEE 基础导线、电源或 RLC，不把删除 CEE 依赖列为退出条件。

## 4. 数值与生命周期验收

| 用例 | 验收重点 |
|---|---|
| DC 分压、开路与短路 | 极性、KCL/KVL、端口功率，区分物理大电流与求解失败 |
| 单相／三相 AC | 相位、线／相电压、中性点、有功与 RMS 统计 |
| RC/RL 阶跃、整流与负载变化 | 时间常数、储能、纹波、步长细化趋势 |
| BJT／MOS | 工作区边界、反接、负载与参数变化、收敛状态 |
| 动态与热学 | 同 dt 不同迭代数无时间漂移；增加微步数后误差趋稳 |
| 失败注入 | 奇异、迭代上限、NaN/Infinity、过期结果不触发不可逆世界效果 |
| 世界生命周期 | 保存重载、拆除、旋转、卸载及重入后状态一致 |
| 高频边界 | 欠压降低能力／停机，输出正确带载，有源增益消耗供电 |

解析解优先，ngspice 提供离线对照，KiCad 可辅助绘制最小电路。必须对齐简化模型、参数、初值、温度、端口方向与采样窗口；不能将复杂 SPICE 模型与游戏简化模型的所有差异算作错误。[ngspice 测试资料](https://ngspice.sourceforge.io/quality.html)

每个测试单独设绝对／相对容差和参考解有效范围；接近零时避免相对误差失真。线性基准可从幅值 1%、相位 1° 的实验目标起步，但这些不是统一质量保证。非线性用例必须记录收敛信息，功率／能量测试还需规定统计区间。

纯模型单测、CEE 集成电路测试和 Minecraft 生命周期测试是三个不同层次；模型单测通过不代表世界集成正确。

## 5. 性能基准与改造门槛

分别测大量小电网、一个大电网、非线性密集电网、频繁拓扑变化与不同微步数。记录 CPU、JVM、线程、堆、制品指纹、节点与元件构成；场景、精度与采样设置一致才比较速度。

阶段指标覆盖图构建、优化、矩阵组装、非线性迭代、线性求解、结果回写及主线程等待。报告 p50/p95/p99、超预算次数、分解次数、迭代数、分配和 GC；嵌套阶段避免重复计时。异步总耗时与主线程等待分开报告。

先依据瓶颈评估对象复用与拓扑／结构／数值分层失效，再比较 EJML 等候选；只有收益与跨平台成本有明确依据时考虑 KLU。更换后端不得以放宽容差或丢弃失败样本制造性能提升。

音频／RF 单独测采样率、包络带宽、并发信道、订阅量、缓冲和端到端延迟，不能用 20 Hz 更新冒充音频精度。发布上限由目标硬件与可重复实验决定，不在文档中预先保证。
