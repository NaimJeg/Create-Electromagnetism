# 上游、内容来源和 Airwaves 调查

原调查日期：2026-11-02；路线纠正：2026-11-03。下文源码快照、Power Grid 与 Airwaves 内容保留为历史调查，本次未逐项复核；不将历史结论视为当前依赖 JAR 的接口保证。调查时间和固定提交见[来源表](../sources.md)。这里将 CEE 视为当前运行时上游，将 Power Grid（交错电网）视为历史内容来源和同类技术参考，将 Airwaves 视为无线电玩法参考。

## 1. CEE 实际已有的能力

上游已经明确提供实验性 AC 玩法：微步设置、三相发电、频率表、同步表、并网相位及三角形／星形变压器连接。因此不能将 CEE 描述为只有直流，也不能以“增加 AC”为理由重建内核。本次读取的[官方交流说明](https://github.com/george8188625/Create-Electro-Energetics/wiki/Alternating-Current)比仅根据 README 推断未来路线更直接。实验性表示功能仍可能变化，不表示这些能力不存在。

旧调查记录的固定源码快照提供以下基础，复用前需与目标制品核对：

| 层次 | 已核查实现 | 可借鉴部分 |
|---|---|---|
| 世界与电网 | `InfrastructureSavedData`、独立设备状态、节点与导线 | 区分电路状态与方块加载状态 |
| 调度 | `SimulationTicker`：主线程 preTick，单独执行器求解，endTick 等待结果并 postTick | 快照提交和结果消费的阶段划分 |
| 拓扑 | 连通域识别、接地、网络化简 | 独立电气岛、无变化拓扑复用的方向 |
| 方程 | `Network.formMatrix()` 组装 MNA，支持电压源及耦合约束 | 元件印章与求解器分离 |
| 数值 | LU / Cholesky 路径、非线性迭代、micro tick 前后回调 | 优先复用既有低频交流求解 |
| 元件 | 电容、电感、二极管、Norton 非线性等效、三相发电机 | 方程与状态如何映射到玩法 |
| 结果 | micro tick 电压数组、有效值及双节点电压查询 | 波形和统计值必须分开提供 |

上述为旧文档的源码调查记录；本次未重新取得该固定提交的源码正文，不宣称已再次核实全部实现。[C2](../sources.md#c2)

### micro tick 的数量级限制

该快照 `CSimulation.microTicks` 默认 1，允许 1–64。按正常 20 TPS、每游戏刻推进 0.05 秒模拟时间计算：

`fs = 20 × microTicks`，`dt = 0.05 / microTicks`。

最大配置为 1280 步/模拟秒；50 Hz 只有 25.6 步/周期。640 Hz 的 Nyquist 边界仅是采样理论上限，不是电路积分的精度保证；非线性和快速边沿还需要更多采样。16 kHz 音频每游戏刻已有 800 个样本，无法直接塞进这套全局 64 步上限。

如果以每周期 32 步举例，直接积分 1 MHz 载波每游戏刻约需 160 万步，100 MHz 约需 1.6 亿步。这里是数量级推导，不是性能实测。高频方案必须改变信号表示，而不只是扩大配置上限。

### 优先验证与局部改进的候选

- `endTick()` 的 `future.get()` 仍可能阻塞游戏主线程；单独线程并不自动带来可控 tick 延迟。
- 先分别测量图构建、优化、组装、迭代、线性求解、回写和等待；瓶颈有证据后再评估增量更新和缓存。
- `Network.runSolver()` 的固定残差阈值和迭代上限需要用目标设备的量纲、范围与误差容限验证；达到上限后返回结果也不等价于收敛。
- 核验 `MicroTickingElectricalProperties`、`NonlinearProperties`、`NortonCoupleNonlinearProperties` 等接口的实际契约和多端耦合能力；先用最小用例证明缺口，不预设必须另建多端口求解器。
- 本项目纯数学设备模型应与世界对象、NBT、Minecraft 类分离，通过 CEE 适配层接入。[C2](../sources.md#c2)

### 实际依赖与开发源码不能混用

本次核验本地缓存：构建文件锁定 Curse Maven 文件号 `9173792` 的缓存 JAR 声明为 `1.21.1-1.1.4`，没有项目引用的 Norton 类；旧调查记录的 CEE `1.21.1` 源码快照声明 `1.21.1-1.2.0`，包含这些类。二进制发布依赖与开发源码快照不同，不能用“最新分支有这个类”推断发布 JAR 能编译。本次未重跑构建；接口缺失是已核验事实，完整编译错误仍待 M0 复现。必须固定经过验证的制品与源码对应关系。元数据声明的最低版本与根 README 也尚不一致，见[本地依赖基线](../sources.md#local-baseline)。[C1](../sources.md#c1)、[C2](../sources.md#c2)

## 2. Power Grid 值得参考的部分

Power Grid 固定快照有独立 `IMNA` 接口，提供 Java 与 Native 后端入口；电容等元件通过残差、外层迭代回调和时间步接口接入。电路板组件、布局与电气网络也分成不同层。其 README 明确区分模组构建与可选原生加速库构建。[P1](../sources.md#p1)

建议借鉴模型接口、拓扑/求解/表现分层和离线测试思路。Java 参考后端与可替换加速后端可以共用语义；原生后端应在性能数据证明有必要后再选。本次没有对其全部模拟器进行质量审计，不把已有实现视为正确性证明。

本项目未来不以移植 Power Grid 新方块作为路线。已有灯具、模型、材质的历史来源仍需保留可追溯记录；改变定位不会改变既有文件的来源。

## 3. Airwaves 必须按版本区分

### 3.1 原发布版本的社区重建（AW-R）

仓库自述来自 `airwaves-1.21.1-0.1.1-atm10.jar`，并说明不是正式上游源码。以下是该重建实现的调查结果，未逐方法对照原二进制。[A1](../sources.md#a1)

| 机制 | 该快照实际实现 | 对本项目的启示 |
|---|---|---|
| 调谐 | `Tuning` 储存 FM/AM 标志和频率；四舍五入后精确匹配频道 | UI 可借鉴；真实选频应由电路带宽和频偏决定 |
| 频段 | FM 87.5–108 MHz、AM 530–1700 kHz | 只是该模组玩法范围，不是本项目频段限制 |
| 传播 | `quality()` 按归一化距离和 FM/AM 经验曲线得到质量；叠加地形、天气、干扰 | 交互反馈可借鉴；不能代替频率相关信道 |
| 收台 | `best()` 从匹配频道中选择质量最高的发射源 | 不支持本项目所需的相干叠加、拍频与电路内混频 |
| 天线 | 天线柱高度和等级影响距离/增益，八木方向影响方向性 | 可设计玩家可见的增益、方向和带宽，而非照搬倍率 |
| 电路板 | 邻接元件对识别为 TANK、OSCILLATOR、TRANSISTOR_AMP、LOGIC 等 Stage，再生成程序 | 玩家操作体验有价值；其功能识别不等于求解器件电压电流 |
| 三极管 | `BoardAnalysis.pair()` 将电阻+三极管识别为放大器、两个三极管识别为逻辑门 | 新项目需要真正 B/C/E 端口、偏置与负载效应 |
| 音频 | 客户端采音、语音帧路由；有 Simple Voice Chat 的 Opus 解码接入 | 编解码属于传输边界，不应成为电路内部表示 |
| 其他内容 | 发射机、接收机、麦克风、扬声器、中继、便携设备、录音等类 | 本次只取与目标相关的机制，不自动扩大设备范围 |

调谐、传播和天线证据见 [A1](../sources.md#a1)，电路板和音频见 [A2](../sources.md#a2)。

该实现的语音工作采样率为 16 kHz，兼容入口包含 48 kHz Opus 解码；`RadioNetwork.send()` 传递音频字节和质量、FM、增益等参数。这支持“无线路由与效果层”的判断，而不是“从完整 RF 电压波形解调出音频”的证明。[A2](../sources.md#a2)

### 3.2 后续社区重写（AW-C）

该仓库 README 描述重写与移除强制 Sable 依赖的方向。固定快照的 `Modulation` 是携带 `rangeFactor` 的记录，FM/AM 注册值分别是 1.0/1.3。仅凭这些类型不能声称它已有非线性载波调制求解器，也不能把 AW-R 的完整功能清单当作该分支当前状态。[A3](../sources.md#a3)

### 3.3 器件级无线电的长期验证目标

以下保留为器件级路线的验证目标，不作为首期高频行为原型已经具备的能力。首期范围及 CEE 边界以[无线电设计](../architecture/radio-and-instruments.md)为准。

1. BJT 放大器输出应由工作点、输入幅度和负载决定；错误偏置要产生失真或截止。
2. AM 边带、混频和包络检波应来自电路计算，不依靠识别某个“正确配方”后激活预置功能。
3. 接收天线注入模拟信号；只有玩家接收电路才能得到解调输出，不能把原音频绕过电路直送接收端。
4. 同频干扰由信号叠加进入电路；不能在传播层一律只保留最强台。
5. 示例蓝图可以指导玩家搭电路，但器件级实现仍须通过端口模型计算，不能用配方识别冒充数值结果。

CEE 仓库标识 MIT；Power Grid 提供 Apache-2.0 及 NOTICE。AW-R README 将重建来源声明为 CC BY-NC-SA 4.0；AW-C 则分别声明资源保留所有权利和自定义代码条款。它们不是同一种授权，不能因为源码可见就合并复制。[P1](../sources.md#p1)、[A1](../sources.md#a1)、[A3](../sources.md#a3)

本次仅记录机制与独立设计，未引入上述第三方源码或资源。后续若复用文件，应按具体文件来源记录许可与署名；“独立实现”与“导入现有代码”应在提交中明确区分。这不是对许可适用性的法律结论。

## 5. 尚不能由调查确定

- 未找到可作为正式基准的原作者 Airwaves 源码发布；重建结果与原发布二进制的完全一致性未验证。
- 本项目需支持多少节点、多少并发无线频道、多少在线音频输入，还没有基准数据。
- 未证实 CEE 未来发布路线和制品稳定性；当前复用方案只依据固定制品，不依赖其未来承诺。
- 尚不能仅凭资料选择 HB/包络求解库，也不能承诺所有玩家电路自动转换为高效包络模型。
