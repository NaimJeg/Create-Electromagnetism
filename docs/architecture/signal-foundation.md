# 麦克风与示波器公共信号层

当前实现位于 `core.signal`，仅依赖 JDK 与既有纯内核。它提供输入与观测数据结构，不是音频电路求解器，尚未接入游戏设备。

## 当前能力

| 层 | 已有能力 | 尚缺边界 |
|---|---|---|
| 器件模型 | 热电阻、集中热容、BJT、MOS，多端电流与雅可比 | 数值回归、CEE 模型适配 |
| 设备运行时 | 固定步参数、提交/丢弃、能量样本、会话与拓扑身份、过期标记 | 全网调度、CEE 微步回调与收敛证明 |
| 音频输入 | 单声道归一化 PCM、样本索引到仿真时间的映射、确定性正弦、有界队列 | 声源范围、真实采音、网络归属校验、重采样、供电与换能器 |
| 波形观测 | 有界历史、差分电压调试探针、质量标记、时间加权均值/RMS、边沿定位 | 有负载的探头、完整触发采集、频率估计、显示抽取、订阅与 UI |

## 使用契约

- `SampleClock` 的原点由适配器指定为仿真秒；不自动追赶墙钟。一个 `AudioInputBuffer` 对应一个流与固定采样时钟；重新开始采音应创建新实例。
- `AudioFrame` 是不可变、最多 4096 样本的单声道帧，幅度在 [-1, 1]，不是电压或声压。声压标定与有限源阻抗模型未实现。正弦相位相对于样本索引零点，原点仅用于时间映射。
- 音频队列拒绝重叠、重放与不同采样时钟，允许向前跳过丢失区间并累计缺失样本。满队列丢弃最旧整帧，累计丢弃样本。空队列返回空，不生成伪造的静音帧。网络适配器还必须在分配帧之前限制包大小，并验证发送者、设备归属、允许的时间范围与速率。
- `WaveformBuffer` 每个通道/会话使用单独实例。只在每个已接受微步提交后调用 `appendDifferential`，不能每 tick 读取一次最后快照来代替完整波形。此接口是无负载调试探针，不模拟物理输入阻抗。
- 适配器需在失败、过期或缺失处显式追加无数值的质量样本；移除、重接线或更换会话时重建缓冲，避免混合不同电路。缓冲自身不校验设备身份。波形时间必须严格递增，快照不可变；累计覆盖数用于告知观察者历史已截断。
- 统计覆盖传入列表的完整首尾时间区间，按梯形法分别积分值与平方值，再计算均值和 RMS；不等同于对线性插值曲线精确积分平方。少于两个样本或窗口含任何无效样本时返回空。有效但稀疏的采样无法自行检测混叠；统计结果不承诺带宽足够，调用者须携带采样限制。
- 边沿查找返回首个阈值交越的插值时间，支持上升/下降；不跨越无效样本。尚不提供迟滞、预触发保留或自动重臂。

## 验证与接入顺序

在仓库根目录执行 `./scripts/test-signal.ps1`，以 Java 21 独立编译全部纯内核并运行信号回归，不依赖 Minecraft 启动或 JUnit 下载。覆盖跨帧正弦连续性、PCM 防御性复制/非法值、奈奎斯特边界、队列溢出/重放/缺帧、正弦 RMS、不等间隔统计、触发、无效数据与历史快照。

2026-11-03 初始验证：独立检查通过，当时整项目编译因 CEE Norton 接口缺失而失败。随后[全仓库重构](package-layout.md)将纯内核迁至 `core`，增加固定制品适配并恢复编译；信号检查也接入 Gradle `verifySignals` / `check`。编译通过不代表游戏内运行已验证。

下一步先固定兼容的 CEE 制品和接口，建立微步提交/失败到波形缓冲的适配；随后补充有限源阻抗的麦克风换能器，并验证实际电网允许的带宽。真实音频输入需独立确定采音依赖及声源范围；16/48 kHz PCM 的容器支持不代表电网可以以该采样率仿真。
