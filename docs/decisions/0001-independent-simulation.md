# ADR-0001：优先复用 CEE，重构设备模型与扩展边界

初稿：2026-11-02；修订：2026-11-03。状态：按本次纠正采用复用优先方向；具体接口和算法仍待实现验证。保留原文件路径以维持既有链接。

## 背景与修订

旧稿将独立内核、多分析后端和最终移除 CEE 写成默认路线。本次撤销这些预设：CEE 已有实验性交流能力，不能用“增加交流”证明重写求解内核的必要性。开发源码与依赖 JAR 的差异应作为基线问题处理，也不能直接推导出独立求解器需求。[调查](../research/upstream-and-airwaves.md)

## 采用的方向

1. 复用 CEE 拓扑、交流元件、微步进和求解过程，保留单一电网求解权威。
2. 优先重构本项目设备模型、状态所有权、扩展接口和验证体系，保留现有内容。
3. 纯数学模型可脱离游戏测试；运行时经集中 CEE 适配层接入，优先正式扩展点。
4. 先实现固定微步的接受／失败／提交语义，再考虑全网回滚或自适应时间步。
5. 高频采用单独抽象，通过受功率约束的源／负载与 CEE 双向耦合。
6. ngspice 首先用于离线对照；CircuitJS、XSPICE 用于生命周期与混合信号设计参考。

## 三层改动范围

| 层级 | 进入条件 | 交付物 |
|---|---|---|
| 设备运行时重构 | 当前工作重点 | 可测试模型、统一端口和状态契约、CEE 适配层 |
| CEE 聚焦改进 | 用例证明接口／诊断缺口或基准定位瓶颈 | 最小上游贡献或受控 fork，附回归测试 |
| 独立电气内核 | 满足下述启动条件并完成新 ADR | 替代方案比较、兼容与迁移计划、行为基准 |

独立内核至少需要证明一种条件：核心需求无法由现有接口及局部扩展正确表达；可重复基准表明结构性瓶颈无法由局部改造有效解决；必要的新分析或时间推进方法与现有实现根本冲突。提出问题、最小复现、局部方案评估及代价比较后再决策。

允许完整重构不等于已经决定替换实现。即使未来替换，也必须保留已有 AC 行为基准；不能让两个求解器共同决定同一网络的节点值。

## 暂不采纳的默认路线

- 不为 AC 从零建立重复的节点方程或电气时钟。
- 不把移除 CEE、HB／包络通用求解器或自适应步长列为首期必交项。
- 不将原生 SPICE、KLU 或商业仿真器绑定为模组运行时依赖。
- 不用高微步数或“在独立线程上”代替性能测量。

## 更新规则

新决策记录具体触发问题、证据、替代方案、验收结果及存档影响。未完成测试不得将“建议”改为“已验证”；产品抽象范围发生变化时明确修订，不能静默改写能力承诺。

## P0—P5 实施补记（2026-11-03）

固定制品的微步接口无法直接表达完整三端雅可比，当前已实施受控局部扩展：仅对包含本项目 BJT/MOS 的 CEE 岛保留端子、添加完整方程，在同一岛内使用 CEE LU 做最多 64 次非线性残差迭代。没有另建电网或电气时钟。带载、N/P 镜像、偏置与实际世界岛用例通过；线性路径仍沿用原后端。代价是这些岛暂不做拓扑消元，稀疏快照/迭代增加开销，规模上限须另做 profiling。AM 使用受功率约束的行为抽象，不以此宣称任意 RF 能力。
